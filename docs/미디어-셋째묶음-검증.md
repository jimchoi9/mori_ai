### G3 기능 검증

- 프론트 굿즈14 upload+4 workspace+3 workflow =21개 통과. 401/403/422/500/503/네트워크/전처리20MiB초과에서 기존 source·revision/history·선택·비기본 placement·draft·생성 가능 상태를 유지하고 할당된 후보만 정리한다. PUT/미리보기 실패 및 생성응답/업로드 중 이탈 검사도 유지한다.
- 실제 격리 HTTP/DB/codec 검사25개 통과(67.34초), migration up/down/up/check 통과. 정확40MP JPEG→2048×1280 WebP 성공,48MP JPEG→422 IMAGE_PIXEL_LIMIT_EXCEEDED 확인. 기존 형식/손상/용량/HEIF회전/HDR·10bit/메모리·timeout·admission 검사 포함. 초기24개 결과는25개와 합산하지 않는다.
- 실제 Chromium 입력9종과 교체 실패7종 및 이탈 폐기 통과. JPEG/PNG 작은 입력 확대없음,20MP EXIF6 JPEG→1638×2048,40MP→2048×1280,20MP PNG/48MP JPEG/HEIC MIME·빈MIME는 원본fallback. 원시 결과는 [브라우저 관측](미디어-셋째묶음-browser.json).
- 실제 React/Canvas/file input을 사용하지만 HTTP는 통제된 모의 응답이다. 화면 Canvas·선택 시안·draft 보존을 확인했고 내부 source/placement는 별도 hook 검사다. 인증 AuthGate는 범위 밖이며401 이벤트 단위검사와 전체 로그인 이동을 구분한다. 브라우저→실제backend/R2 전체 E2E는 수행하지 않았다.
- 재현 도구: `frontend/tests/goods_browser_probe_setup.sh`, `.cjs`, `.md`. 기존 로컬 Docker이미지/Playwright를 사용하고 합성 fixture를 생성한다. 외부 요청을 차단하며 의존성 다운로드·설치·사용자사진 검색은 하지 않는다. `iphone.heic`은 합성 파일명이다.
- WebKit 기대 revision2336이 없어 설치2272로 한 번 확인했지만 `PushAPIEnabled` protocol 불일치로 실패했다. 이후 재시도/다운로드하지 않았다. WebKit·실제 iPhone은 미검증이며 성공으로 계산하지 않는다.
