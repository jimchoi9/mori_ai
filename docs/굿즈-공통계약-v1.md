## v1.13 실제 AI 후보만 표시 — 2026-10-23

사진/시안 첨부 후에는 기본 문구를 선표시하지 않는다. Luna 응답 전에는 찾는 중 안내만 보여주고 유효한 실제 응답만 후보로 표시한다. 다른 제안은 다음 batch를 요청하며 기존 AI 후보는 응답이 도착할 때까지 유지한다. 실패/disabled/pending은 기본문구로대체하지않고상태를알린다. 기존 batch0~3 한도 이후에는 버튼을비활성화하고한도를안내한다. 후보복제/로컬목록순환없음. 동일조건 캐시응답은 실제 과거 AI 응답일 수 있으며 매번 새 호출을 보장하지 않는다.

## 상태와 보관

- 임시 work: active → completed 또는 discarded → cleaned. active는 생성 후 24시간 만료한다. 복원 목록/초안 저장 UI를 제공하지 않는다.
- revision: queued → running → ready/failed/unknown. unknown은 공급자 재호출 없이 기존 저장 결과만 회수한다. 실패한 시안을 수정 부모로 쓸 수 없다.
- 디자인: 사용자가 선택한 ready 시안과 고리 위치를 완성 저장한다. work당 1개로 멱등 저장한다. 내 디자인 목록에는 완성 디자인만 표시한다.
- 작업 폐기 확인·사진 교체 성공 시 임시 work 접근을 차단한다. 실제 파일 삭제는 worker가 처리한다. 브라우저 강제 종료는 종료 요청을 보장하지 않으므로 TTL로 보완한다.
- 서버 작업/중복키/비용 기록은 사용자용 작업 저장과 다르다. 영속 비용 기록은 작업 폐기로 삭제하지 않는다.
- 현재 제작 PDF·메일·주문 접수 API는 범위 밖이다. 제작 연동 시 goods_designs.production_started_at을 디자인 잠금 아래 설정해야 하며 이후 앨범 변경을 서버에서 거부한다.

## v1.9 짧은 요소 추천과 순환 — 2026-10-23

- 추천은 완성 문장 대신 한 가지 디자인 결정을 담은2~24자 요소다. HTTP items에 category(medium/background/border/color/composition/subject/decoration)를 추가한다. AI는9개·최소3범주를 제안하며 그림체/배경/테두리 등 서로 다른 범주가3개씩 섞이도록 지시한다. 같은 결정의 대안은 같은 범주를 쓴다. 예: 수채화/색연필/3D는 medium, 단순/풍성 배경은 background. 외곽 모양은border, 모서리 꽃 등 붙인 장식은decoration이므로 사각형+꽃 장식을 함께 선택할 수 있다.
- 화면은3개씩8초 간격으로 이미 받은 후보만 순환한다. 자동 순환은 추가AI 호출을 하지 않는다. 최초 유효 맥락 진입과 명시적 ‘다른 제안’만 기존 상한 안에서 요청한다. 읽는 버튼에 새 응답을 즉시 덮어쓰지 않는다. 맥락별 순환 후보는최대36개, 브라우저 맥락 캐시는16개다.

- 선택한 요소는 초안에 한 줄씩 추가한다. 같은 범주의 다음 선택은 이 컴포넌트가 삽입한 수정되지 않은 줄만 교체하며 다시 선택하면 해제한다. 사용자가 직접 작성·수정한 문장은 삭제하지 않는다. 편집한 줄은 소유권을 잃어 자동 교체하지 않으므로 사용자가 모순된 문장을 직접 남기는 경우까지 해소하지 않는다.3000자 상한, 직접 전송, 기존 이미지 무료3회 정책 유지.

- `POST /claim {work_id}`는 승인된 회원+Origin/CSRF를 요구한다. 회원·cookie의 비회원 principal 행을 정렬 잠금한 뒤 work를 잠가 소유권을 원자적으로 이전한다. 타인/만료/폐기404, queued/running/unknown409, 이미 같은 회원에게 이전된 활성 작업은200이다. 결과 파일은 복사/재생성하지 않고 기존 result/source key를 보존한다. 중복 인계에도 작업 하나를 유지한다. 이전 후 비회원은 접근 불가, 완성/테스트 결제는 기존 회원 경로를 따른다.
- 고리 배치/선택 복원 후 사용자가 저장을 다시 확인한다. 로그인만으로 저장·결제·앨범 생성하지 않는다. 로그인 후 생성 횟수 정책은 기존 회원 설정을 따르며 무료 횟수 재지급을 안내하지 않는다.
- 요청과 결과를 한 대화에 누적 표시하고 선택한 시안/수정 부모를 안내한다. 예시는 별도 확대 모달, 고리 배치/저장은 대화를 보존하는 굿즈 미리보기 모달이다. 새 대화는 확인 후 기존 작업을 폐기하되 비회원 잔여 한도를 재지급하지 않는다. 대화 중 사진 추가/제거·성공한 사진 교체 시 이전 이력 유지, 로그인 회원의 미완성 작업 복원과 구매 직접 의도는 후속이다. 현재 성공한 사진 교체는 경고 확인 후 기존 작업을 폐기하며 실패는 이전 시안/입력을 보존한다.

## v1.5 키링·마그네틱 선택과 상품 종류 보존 — 2026-10-22

- 사용자 확정: 브랜드는 Mori 유지, 마그네틱 추가, 3가지 비교는 아직 추가하지 않는다. 완성 PNG 불러오기는 참고 사진 첨부와 달리 이미 완성된 PNG를 AI 없이 시안으로 가져와 굿즈 미리보기/저장으로 넘기는 기능이라고 설명했으며 사용자 결정 전에는 구현하지 않는다.
- 공개 진입의 상품 선택은 `keyring|magnet` 두 값이다. 선택에 따라 기존 로컬 예시·확대 이미지·미리보기·문구가 바뀐다. 같은 시안을 상품 간 전환할 때 AI를 자동 호출하거나 비회원 횟수를 차감하지 않는다. 마그네틱은 고리/구멍 없이 기존 renderer의 아크릴 실루엣을 사용한다.
- 생성 요청의 선택 `product` 기본keyring. 기본keyring은 기존 멱등성 해시에서 생략해 과거 요청과 명시적keyring 재전송이 같은 revision을 반환한다. 다른 상품으로 같은 키를 재사용하면409. 새 config에 product를 동결하고 revision 응답에도 product를 추가한다. 과거 config 누락은keyring으로 읽으며 기존 진행 요청의 prompt/config를 변경하지 않는다.
- 마그네틱 신규 생성은 `goods-pilot-magnet-v1` 프롬프트로 고리/구멍/노출 자석 없이 인쇄용 artwork를 요청한다. 키링은 기존 `goods-pilot-v1` 본문/버전을 유지한다. 공급자·모델·투명PNG 검증·이미지 전역2·비회원 합산3회·SDK 유료 재시도0은 그대로다. product 선택으로 추가 이미지 수를 요청할 수 없다.
- complete 요청의 선택 `product` 기본keyring, 응답/디자인 목록/상세는 product를 반환한다. 기존 placement의 widthMm은 공통이며 holeX/Y는 마그네틱 렌더에 사용하지 않는다. 이미 완성된 work는 같은 revision/placement/product에서만 멱등 응답하며 상품을 달리 보내면409다. 저장할 때 선택한 상품을 확정하므로 이미 만든 artwork를 다른 상품으로 저장할 수 있다.
- migration `0010_goods_products`는 goods_designs.product를 nonnull/defaultkeyring 및 enum check로 추가한다. 기존 디자인은 키링으로 읽으며 기존 구매 snapshot·앨범·예약/run을 재작성하지 않는다. 마그네틱 디자인이 남아 있으면 downgrade는 종류를 잃지 않도록 거부한다.
- 저장 로그인 의도에 product를 포함해 OAuth/개발 로그인 왕복 후 같은 상품으로 미리보기를 복원한다. 과거 product 없는 인계 정보는keyring, 알려지지 않은 값은 거부한다. 단순 새로고침의 작업 복원은 최근 생성 revision의 상품을 사용하며 미전송 상품 선택까지 저장하는 기능은 아니다.
- 신규 테스트 구매 snapshot은 product를 함께 동결한다. 기존 snapshot을 backfill하지 않는다. 디자인 상세와 내 디자인 목록도 저장된 상품을 사용하고 구 API/캐시의 product 누락은keyring으로 표시한다. 실제 결제/제작 발주·상품 가격/장수/배송·PNG 가져오기 API는 추가하지 않는다.

### 2. 비회원 소유권·첨부·대화 처리안

- 서버가 비회원 세션을 발급하고 자신의 work·revision·첨부·결과만 접근하도록 한다. 기존 회원의 앨범/디자인·공개하지 않은 미디어 권한을 넓히지 않는다. 기존 승인 전용 회원 모드와 공개 굿즈 체험 정책을 분리한다.
- 세션 비밀은 서버 검증 가능한 HttpOnly cookie로 관리하는 안을 기본으로 하며 URL/localStorage 관리키를 원본 파일럿에서 복사하지 않는다. cookie 인증 변경 요청은 Origin/CSRF 검증을 적용한다.
- 첨부는 선택→썸네일/첨부 확인→제거/교체가 가능한 대화 입력이다. 사진 없는 첫 생성, 사진 기반 첫 생성, 선택 결과 수정의 provider 입력을 구분한다. 수정 요청은 선택 시안과 해당 요청의 첨부 참조를 동결해 이후 사진 변경이 이전 이력/재시도 입력을 바꾸지 않게 한다.
- 사진 교체/업로드 실패가 이전 대화·결과를 폐기하지 않게 한다. 첨부가 실제 서버 업로드 완료인지 로컬 선택 상태인지 구분한다. 사진 처리 동의는 업로드/외부 AI 전송 전에 받되 로그인 강제와 분리한다.
- 기본 한 번 전송은 이미지1장 결과로 설계한다. 파일럿의 참고사진 최대4장·3가지 비교를 이번 확정으로 자동 가져오지 않는다. 첨부 상한은 전처리/메모리·provider 입력과 함께 상세 확정한다.
- 일시 이탈·새로고침·OAuth 왕복 후 같은 세션에서 원래 대화를 복원할 수 있게 한다. 현재 이탈 즉시 폐기 동작은 새 흐름에 맞게 교체한다. 임시 작업24시간 TTL을 초기 후보로 검토하고, 만료/보존/정리와 로그인 왕복 유효기간을 맞춘다. 명시적 새 대화/폐기와 단순 화면 이탈을 구분한다.

### 3. 무료3회·유료 호출 안전장치 처리안

- 한도는 work별이 아니라 비회원 세션의 여러 대화를 합산한다. 새 대화·동시 요청·동일 키 재전송으로3회를 추가 지급하지 않는다. cookie 삭제/다른 브라우저를 동일인으로 완벽히 식별한다고 보장하지 않으며 보조 요청 제한·서비스 전체 차단을 별도로 설계한다.
- API 접수 때 세션 한도를 transaction으로 예약하고 요청 식별자와 연결한다. 동일 요청은 같은 revision·예약을 반환하며 추가 차감/생성을 하지 않는다. 유료 dispatch 전 전체 BudgetLedger와 전역 이미지2 제한도 적용한다.
- 한도 계산의 기술 초안은 `예약 중 + dispatch/결과불명 + 확정 사용 ≤ 3`이다. 명확한 미전송/무과금 거절은 예약을 해제할 수 있고, 전송 여부 불명은 유지한다. 응답 실패의 반환 조건은 dispatch 증거·비용 예약과 함께 상세 명세/테스트에 적는다. 성공 수만 세어 실패/동시 요청으로 과금이 무제한 반복되는 구조를 피한다.
- 3회 도달 후에도 이미 만든 시안 선택·목업·로그인·저장/구매를 제공한다. 로그인하면 무료 횟수가 다시 생긴다는 정책은 아직 정하지 않았으므로 UI에서 약속하지 않는다.
- SDK 유료 재시도0·unknown 자동 재전송 금지·원래 결과/영수증 복구를 유지한다. 개발 검증 총 승인USD100/초기USD5와 모델·가격 검토 조건은 바꾸지 않는다. 이 초안 작성으로 실제 유료 호출을 실행하지 않는다.

### 4. 로그인 후 작업 인계 처리안

- 저장/구매 버튼은 현재 선택 revision·대화·반환 위치와 원래 의도를 서버가 검증할 수 있는 인계 정보로 보존한 뒤 OAuth로 이동한다. 임의 외부 redirect·URL에 비밀 token 노출을 허용하지 않는다.
- OAuth 성공 시 세션의 비회원 작업 소유권을 확인하고 로그인 사용자에게 한 번 귀속한다. 비회원 상태를 단순히 현재 로그인 계정 ID로 치환하지 않는다. 중복 callback/탭·다른 계정 경합·만료·소유권 불일치를 처리한다.
- 원래 선택한 결과와 저장/구매 의도로 복귀한다. 로그인이나 인계만으로 디자인을 재생성·구매 확정·앨범 개설하지 않는다. 기존 세션 초기화가 비회원 인계 대상을 먼저 지우지 않도록 수명주기를 설계한다.
- 새로고침/네트워크 오류 후 인계와 저장 요청은 같은 결과를 반환한다. 회원의 기존 디자인/사진첩은 비회원 대화와 격리한다.

### 5. 구매 완료와 전용 앨범 자동 개설 처리안

- 디자인, 구매/주문, 구매한 굿즈, 앨범 권한을 구분한다. 저장된 디자인은 구매 없이 존재할 수 있다. 같은 디자인의 재구매/수량 처리가 가능하므로 현 `GoodsDesign.album_id` 하나를 모든 구매의 대응 관계로 고정하지 않는다.
- 서버가 검증한 구매 완료만 앨범 개설 권한을 만든다. 브라우저의 성공 화면/클라이언트 flag·디자인 저장·파일럿의 제작확정/메일 접수를 결제 완료의 근거로 사용하지 않는다.
- 구매 식별자와 확정된 앨범 권한 단위에 unique/idempotency 제약을 두고 전용 빈 앨범과 연결을 영속화한다. 동일 완료 통지/재시도는 동일 앨범을 반환한다. 미결제·실패에는 개설하지 않는다.
- DB 반영 실패/완료 이벤트 중복에 대비해 구매 확인과 outbox/개설 job을 원자적으로 기록하는 경계를 설계한다. 사용자는 필요 시 ‘앨범 준비 중’을 거쳐 이미 연결된 사진 채우기 화면으로 이동하며 기존 앨범 선택 단계는 없다.
- 구매 이후 앨범 생성뿐 아니라 해당 신규 앨범의 업로드 예약·complete·생성 dispatch에도 구매 권한을 검증한다. 단순히 ‘새 앨범’ 버튼만 숨기는 방식으로 대체하지 않는다.
- 기존 독립 앨범·업로드 예약·진행run·기존 수동 연결은 소급 차단/삭제/재작성하지 않는다. 새 구매 기반 경로와 legacy 데이터 경로를 명시적으로 구분한다. 이전 API의 무제한 신규 개설을 새 경로에서 우회 수단으로 남기지 않는다.
- 주문/결제 제공자, 상품별 장수·기간·수량별 권한 대응, 취소/환불 후 앨범 접근은 구매 묶음 상세 설계 대상이다. 참고 문서의 기본20/확장50·연장·NFC 등은 이번 초안에서 공통계약의 실행 한도로 일괄 이식하지 않는다. 실제 PG 연결/실거래·외부 제작 주문·운영 배포는 별도 실행 범위다.

### 6. 현재 구현과 달라지는 경계 및 인수 기준

## v1.16 구매 후 자료·사진 추가·선물 등록 — 2026-10-26

사용자가 지정한 TASK-002 `03_질의응답과_결정.md`의 로그인 소유권 정책과 약5×5cm, 운영자1인 수신을 반영한다. 실제 PG·제작 발주·NFC 감상 인증 전환은 제외한다.

- `POST /goods/designs/{id}/test-checkout`: 기존 `expected_version`에 선택 `gift: boolean=false` 추가. false/누락의 기존 멱등 해시는 유지한다. 같은 디자인의 일반/선물 구매 구분 변경은409. 구매·전용draft 앨범·outbox·멱등 응답을 한 트랜잭션에 기록한다. 네트워크·메일 실패나 다른 멱등키로 앨범을 추가 생성하지 않는다.
- 일반 구매는 구매자 소유. 선물 구매는 앨범을 자동 생성하되 `management_pending=true`로 책장/업로드/생성 접근을 차단한다. QR 열기·로그인·inspect는 소유권을 바꾸지 않는다. 최초 명시 등록만 같은 앨범의 owner를 변경하고 pending을 해제한다. 구매 자료 소유자는 구매자 그대로다. 동시 등록은 행 잠금으로1명만 성공하며 임의 양도·공동 편집은 없다.
- `POST /goods/purchases/{id}/gift/inspect|claim`: 회원+CSRF, body `{token?: string|null}`. 256bit 비밀 QR token의 hash를 검증한다. token은 fragment에 넣어 HTTP/OAuth URL 로그에서 제외하고 현재 탭 sessionStorage로 로그인 왕복을 이어간다. 최초 등록 후 등록 계정은 token 없이 재접속 가능하다. token만으로 업로드·삭제 권한을 부여하지 않는다. 이미 다른 계정이 등록했으면 `claimed`를 반환한다.
- `GET /goods/purchases/{id}`와 `/files/{original|preview|qr|sheet|spec}`은 구매자 전용. snapshot v2에 revision/product/placement/design_version, 불변 artwork_key, message/style, renderer_version, 좌표계, print_box_mm=50을 보존한다. 원화 PNG는 저장된 바이트 그대로다. 키링의 구멍 중심 안내는 별도 PNG에 표시하며 마그네틱에는 구멍을 넣지 않는다. 원화의 trim 기준 종횡비를50×50mm 안에 맞추고 칼선/부착부/강도 검증을 약속하지 않는다.
- A4 PDF는 실물 배율 원화·별도 배치 안내·업로드QR·50mm 눈금·개발 주소 만료를 담는다. JSON은 구매 당시 상품/시안/배치와 파일 해시를 보존한다. 화면의 금속 고리 목업을 인쇄 원화로 사용하지 않는다. 배치 안내 PNG는 확정 좌표를 재현한 안내이며 화면 목업 스크린샷이 아니다.
- `GET /goods/purchases/by-album/{id}`는 해당 앨범 관리계정에게 구매 화면(구매자) 또는 선물 등록 화면(수령자) 복귀 경로를 제공한다. 구매 화면은 사진 추가를 주 동작으로 두고 QR/제작 자료를 접어 제공한다. `/purchases/{id}/photos`는 로그인 후 실제draft 편집 화면으로 이어진다. 기존 draft 이후 편집 제한은 유지하며 삭제된 앨범의 구매 자료는 재조회할 수 있다.
- QR은 사진 관리 경로다. 감상용 NFC 경로나 공개 감상 권한을 발급하지 않는다. `GOODS_DELIVERY_ORIGIN`은 HTTPS 외부 서비스 주소이며 localhost/loopback은 거부한다. LAN은 local+명시허용+timezone 포함 만료시각이 필수다. 만료하면 QR/PDF 재발급은 중단하지만 구매/사진 추가/원화 다운로드는 유지한다. 주소 설정 변경 시 새 불변 bundle을 만들고 이전 발송 payload를 덮어쓰지 않는다. 인쇄된 LAN QR 자체가 자동 갱신되지는 않는다.
- migration0013은 deliveries/attempts와 선물 보류/등록 필드를 추가한다. 기존 구매 snapshot은 backfill하지 않는다. 과거 구매는 요청 시 자료만 만들고 `not_requested`로 보존하여 메일을 자동 보내지 않는다. 새 구매만 `pending→preparing→sending→accepted|failed|unknown`, 설정 미완성은 `waiting_configuration`. 준비 중 lease 만료는 재준비, 전송 중 중단은unknown으로 남기며 자동 재전송하지 않는다.
- Resend adapter는 운영자 설정주소1개에 원화PNG·배치PNG·PDF·JSON을 첨부한다. 구매자 메일은 보내지 않는다. 공급자 idempotency key는 시도ID 기반이며 timeout/5xx/불명응답은unknown. 명시 retry 시 unknown은23시간 내 동일 payload/key와 동일 주소 설정만 재사용한다. 이후는 `MAIL_RECONCILIATION_REQUIRED`, 공급자 확인 없이 새 시도를 만들지 않는다. 명확한 거절은 새 시도 이력으로 재전송 가능하다. accepted는 공급자 접수이며 받은편지함 도착 증거가 아니다.
- `GOODS_MAIL_ENABLED=false` 기본. key/from/to가 모두 있어도 enabled=false면 전송하지 않는다. `GOODS_MAIL_PURCHASE_ID`를 지정하면 그 구매만 처리하여 테스트 발송 범위를 제한한다. 외부 호출은 구매 트랜잭션 밖 별도 delivery lane에서 수행한다. 파일 렌더링은 DB advisory lock으로 전역1개, 파일/시도 payload는 불변 경로·hash로 보존한다.

메일·QR HTTP 샘플은 `굿즈-공통계약-v1.examples.json`, 실행/미검증 항목은 개발운영 최신 절을 따른다.
