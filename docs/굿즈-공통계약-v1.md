# 굿즈 연동 계약 v1.3

> 2026-10-22: v1.3은 사용자 요청에 따른 임시 테스트 결제·전용 앨범 자동 연결만 추가한다. 비회원 채팅·설명만 생성·로그인 인계와 실제 구매는 문서 하단의 [차기 계약 초안](#차기-계약-초안--비회원-채팅-생성과-구매-후-앨범-2026-10-22)이며 아직 구현하지 않았다. 아래 기존 v1.2 설명 중 테스트 구매 경로는 v1.3 절이 우선한다.

사용자 확정: 이식 계획 10~11절. 기존 사진첩 HTTP 계약을 변경하지 않고 `/api/v1/goods`를 추가한다. 이 문서는 구현 계약이며 실제 유료 연동·제작 가능성 검증 완료를 뜻하지 않는다.

## 상태와 보관

- 임시 work: active → completed 또는 discarded → cleaned. active는 생성 후 24시간 만료한다. 복원 목록/초안 저장 UI를 제공하지 않는다.
- revision: queued → running → ready/failed/unknown. unknown은 공급자 재호출 없이 기존 저장 결과만 회수한다. 실패한 시안을 수정 부모로 쓸 수 없다.
- 디자인: 사용자가 선택한 ready 시안과 고리 위치를 완성 저장한다. work당 1개로 멱등 저장한다. 내 디자인 목록에는 완성 디자인만 표시한다.
- 작업 폐기 확인·사진 교체 성공 시 임시 work 접근을 차단한다. 실제 파일 삭제는 worker가 처리한다. 브라우저 강제 종료는 종료 요청을 보장하지 않으므로 TTL로 보완한다.
- 서버 작업/중복키/비용 기록은 사용자용 작업 저장과 다르다. 영속 비용 기록은 작업 폐기로 삭제하지 않는다.
- 현재 제작 PDF·메일·주문 접수 API는 범위 밖이다. 제작 연동 시 goods_designs.production_started_at을 디자인 잠금 아래 설정해야 하며 이후 앨범 변경을 서버에서 거부한다.

## HTTP

모든 API는 로그인 사용자 소유권을 검사한다. 변경 요청은 기존 Origin/CSRF 검사를 적용한다. 생성·업로드에는 최신 사진 처리 동의가 필요하다. 응답은 기존 data/request_id 및 오류 봉투를 따른다.

새 앨범 만들기는 기존 앨범 생성 API를 쓴다. 완성 디자인은 계속 보관되며 앨범 완성 후 돌아가기 안내를 통해 디자인 상세에서 연결한다. 자동 연결/임시 앨범 연결을 몰래 수행하지 않는다.

## AI와 실행

- 2026-10-18 실제 검증 후 사용자 승인으로 굿즈 기본 모델을 `gpt-image-2.5-sunburst`로 변경했다. 사진첩은 `gpt-image-2`를 유지한다. GOODS_IMAGE_MODEL로 별도 교체 가능하며 요청마다 모델/프롬프트 버전을 동결한다.
- OpenAI Images edit adapter: 사용자 사진1장, 수정 시 선택 시안 + 사용자 사진, 요청당 n=1, PNG/transparent. 모델이 다르면 기존 모델 가격표로 비용을 추정하지 않는다. SDK 재시도0.
- 공식 투명 배경 근거: https://developers.openai.com/api/reference/resources/images/methods/edit . 기존 gpt-image-2 preview는 현재 계정에서 background=transparent 요청을 400으로 거절해 대체했다. 가격은 https://developers.openai.com/api/docs/pricing 의 Standard text/image input/output $5/$8/$30 per 1M을 적용한다.
- 기존 BudgetLedger를 공유한다. 사용자별 생성 제한은 기본 미적용, GOODS_GENERATION_LIMIT는 추후 적용 가능한 선택 설정이다. 개발 검증 총 승인 $100/현재 운영 설정 예산을 임의 확대하지 않는다.
- worker 이미지 슬롯은 사진첩 image_transform과 굿즈 합계 DB 전역2개. 예약 후 실행, 최대310초 공급자 대기,600초 lease. lease 만료 결과는 unknown으로 전환하며 자동 유료 재호출하지 않는다.
- 결과 PNG와 사용량 영수증을 보관한 뒤 비용 정산한다. 재시작 시 기존 결과와 영수증을 회수한다. 모델 교체 시 가격/투명도/출력 검증은 별도 수행한다.

## v1.1 서버 업로드 보완 — 로컬 첫 묶음

G1 서버 경로만 추가했다. 프론트 고해상도 축소·HEIC 선택·오류별 문구는 G2에서 연결한다. 기존 work source bytes/hash·시안은 일괄 변환하지 않는다. 교체는 기존처럼 별도 후보 work에서 진행한다.

- 기존 앨범 v2 정규화 API를 명시 설정으로 사용한다. 입력20MiB/40MP, 출력 긴 변2048·품질85·확대 없음, child512MiB·시간 제한을 적용한다. 출력20MiB 상한이며 앨범 v3의1MB 재사용 상한을 굿즈의 신규 거부 조건으로 추가하지 않는다.
- API 프로세스당 정규화 active1·대기2로 제한하며 body 수신 전에 진입을 제어한다. 대기5초 초과 또는 포화는503 `IMAGE_PROCESS_BUSY`. 다중 프로세스 전체 메모리 검증은 후속 Task7에서 수행한다.
- 용량413 `IMAGE_SIZE_LIMIT_EXCEEDED`, 미지원 형식415 `UNSUPPORTED_MEDIA`, 픽셀/손상/정규화422 각 codec 코드, 처리 timeout/memory/busy503·retryable, 저장소 장애503, 내부 장애500을 구분한다. 인증/권한/CSRF/소유권 검사는 유지한다.
- HEIF 방향 fixture는 실제 container irot가 포함된 serialized EXIF로 검증한다. 10bit/HDR 지원을 새로 보장하지 않는다. 실제 운영422 사진 원인 및 실제 iPhone 검증은 별도 미확정이다. 운영 배포는 수행하지 않는다.


## v1.2 프론트 입력·교체 수명주기 — 로컬 둘째 묶음

- 원본20MiB 상한을 먼저 검사한다. JPEG는 보수적 헤더 검사 후40MP까지 축소 bitmap을 요청하고 방향을 한 번 적용해 긴 변2048·품질85 WebP로 만든다. 작은 사진은 확대하지 않는다. PNG/기본 WebP는12MP까지 처리하며 고해상도 PNG/WebP·HEIC/HEIF·불확실한 ICC/HDR 입력은 서버로 전달한다. 앨범12MP 경계는 유지한다.
- HEIC/HEIF MIME·확장자를 선택 목록에 추가한다. 클라이언트 힌트는 서버 실제 파일·형식·픽셀 검증을 대체하지 않는다. 브라우저 실패는 원본 fallback, 명시 취소는 취소로 전파한다.
- 인증된 source GET의 WebP 미리보기 디코딩까지 성공한 뒤 기존 work를 폐기한다. 후보 업로드·미리보기 실패는 기존 시안/배치를 유지한다. 이탈 시 요청 취소, bitmap/canvas/object URL 정리와 늦은 응답 무시를 적용한다.
- 오류의 HTTP status/code/details/retryable/request_id를 보존한다. 형식·용량·픽셀·디코딩/색상·인증/권한·busy/timeout/memory·서버·네트워크 안내를 구분한다. 비JSON 프록시 상태와401 세션 만료 이벤트를 유지한다.
- createImageBitmap resize 옵션은 모바일 최대 메모리 보증이 아니다. 실제 모바일·전체2GB 부하 검증 및 운영422 원인 확정은 미완료다.

## v1.3 임시 테스트 결제와 앨범 자동 연결 — 2026-10-22

- 사용자 요청: 실제 PG 연결 전에는 임시 결제 버튼으로 다음 과정을 체험한다. v1.3은 현재 로그인된 완성 디자인에서 이 경로를 먼저 연결한다. 비회원 생성·로그인 인계를 이미 구현한 것으로 보고하지 않는다.
- `GOODS_CHECKOUT_MODE=disabled|test`, 기본disabled. 명시적test에서만 신규 테스트 결제를 제공한다. `/api/v1/client-config`에 `goods_checkout_mode`를 추가한다. 기존 QA/운영 환경파일은 자동 변경하지 않는다.
- 완성/디자인 상세에 ‘테스트 결제하고 사진 추가하기’와 실제 요금·제작/배송 요청이 없다는 안내를 표시한다. 설정 로딩/실패 중 결제 버튼을 활성화하지 않는다.
- `POST /api/v1/goods/designs/{id}/test-checkout`: 로그인·승인·소유권·Origin/CSRF·Idempotency-Key, 엄격한 `{expected_version:int>=1}`를 요구한다. test 모드가 아니면404. 최초201, 다른 키로 기존 테스트 구매를 조회하면200. 같은 키/본문은 원래 응답 replay, 다른 본문은409다.
- 응답data는 `{id,mode:"test",status:"simulated",album_id,album_status}`다. 버튼 처리 뒤 album_status에 맞는 편집/진행/검토/감상 화면으로 이동한다. 네트워크 실패 시 같은 키·version으로 재시도한다. 세션 만료/이탈 뒤 늦은 응답으로 화면을 이동하지 않는다.
- 새 `goods_test_purchases`는 owner/design/album·status=simulated·선택revision/placement/version snapshot을 저장한다. 실제 결제 금액·결제 공급자 성공·제작 주문·production_started를 기록하지 않는다. 임시 시험은 디자인당 최대1개·전용 앨범1개이며 향후 실제 재구매/상품 수량 정책과 별개다.
- owner→design 잠금 아래 테스트 구매·빈draft 앨범·연결·멱등성 응답을 같은transaction에 저장한다. 중간 실패는 전부rollback하고 같은 요청을 안전하게 재접수한다. 기존 디자인 저장만으로는 앨범이 생기지 않는다.
- `GoodsDesign.test_purchase`를 추가하고 기존 `album_id`는legacy 연결용으로 보존한다. 테스트 구매가 있는 디자인의 수동 앨범 연결은409로 거부한다. 기존 연결 또는 제작 시작된 디자인에는 테스트 앨범을 덮어 연결하지 않는다.
- 앨범이 삭제돼도 새로운 키로 새 테스트 앨범을 지급하지 않는다. 디자인 조회는 삭제 상태를 표시하고 추가 결제 버튼을 제공하지 않는다. 같은 키 replay는 최초 응답이므로 클라이언트는 확정된 테스트 구매의 최신 상태를 디자인 조회로 확인할 수 있다.
- migration `0008_goods_test_checkout`는 새 테이블만 추가한다. 기존 예약·run·디자인·수동 연결은backfill하지 않는다. 실제 PG/외부 AI/메일/발주/배포는 이 경로에서 호출하지 않는다.
- 이 시험 경로는 새 구매권한 기반 전체 앨범 정책을 구현한 것이 아니다. 기존 독립 앨범 API는 유지하며 구매 전 업로드 차단·실구매 이벤트·환불/수량 정책은 차기 구매 묶음에서 다룬다.

## 차기 계약 초안 — 비회원 채팅 생성과 구매 후 앨범 (2026-10-22)

**상태:** 제품 방향은 사용자 확정, 아래 기술적 처리안은 상세 설계 초안. v1.3의 테스트 결제만 별도로 구현하며 비회원·로그인 인계·실제 구매는 미구현이다. 해당 구현 묶음에서 경로·필드·오류·샘플·검증을 함께 확정하고 구현 기준 버전을 갱신한다. 기존 회원·사진필수·이탈폐기 경로와 아직 구현하지 않은 새 고객 흐름을 혼용하지 않는다.

| 로그인 | 디자인 저장 또는 구매 시작 시 필요. 기존 작업·결과·선택을 이어받고 원래 행동으로 복귀 |
| 디자인 저장 | 계정의 디자인 보관이며 구매나 앨범 개설과 구분 |
| 구매/앨범 | 구매 완료 후 그 굿즈를 위한 앨범을 자동 개설·연결. 구매 전에 앨범 사진을 채우거나 기존 앨범을 수동 선택하게 하지 않음 |
| 주요 이용 예상 | 여행사진 기반 굿즈가 많을 것이라는 사용자 가설. 실제 사용 비중이나 전환율이 검증된 것은 아님 |

권장 순서: `비회원 요청/선택 첨부 → 이미지 결과/수정 → 목업 → 저장/구매 의도 → 로그인/작업 인계 → 저장 또는 구매 진행 → 서버가 구매 완료 확인 → 전용 앨범 자동 개설/연결 → 사진 업로드/처리`.

### 2. 비회원 소유권·첨부·대화 처리안

- 서버가 비회원 세션을 발급하고 자신의 work·revision·첨부·결과만 접근하도록 한다. 기존 회원의 앨범/디자인·공개하지 않은 미디어 권한을 넓히지 않는다. 기존 승인 전용 회원 모드와 공개 굿즈 체험 정책을 분리한다.
- 세션 비밀은 서버 검증 가능한 HttpOnly cookie로 관리하는 안을 기본으로 하며 URL/localStorage 관리키를 원본 파일럿에서 복사하지 않는다. cookie 인증 변경 요청은 Origin/CSRF 검증을 적용한다.
- 첨부는 선택→썸네일/첨부 확인→제거/교체가 가능한 대화 입력이다. 사진 없는 첫 생성, 사진 기반 첫 생성, 선택 결과 수정의 provider 입력을 구분한다. 수정 요청은 선택 시안과 해당 요청의 첨부 참조를 동결해 이후 사진 변경이 이전 이력/재시도 입력을 바꾸지 않게 한다.
- 사진 교체/업로드 실패가 이전 대화·결과를 폐기하지 않게 한다. 첨부가 실제 서버 업로드 완료인지 로컬 선택 상태인지 구분한다. 사진 처리 동의는 업로드/외부 AI 전송 전에 받되 로그인 강제와 분리한다.
- 기본 한 번 전송은 이미지1장 결과로 설계한다. 파일럿의 참고사진 최대4장·3가지 비교를 이번 확정으로 자동 가져오지 않는다. 첨부 상한은 전처리/메모리·provider 입력과 함께 상세 확정한다.
- 일시 이탈·새로고침·OAuth 왕복 후 같은 세션에서 원래 대화를 복원할 수 있게 한다. 현재 이탈 즉시 폐기 동작은 새 흐름에 맞게 교체한다. 임시 작업24시간 TTL을 초기 후보로 검토하고, 만료/보존/정리와 로그인 왕복 유효기간을 맞춘다. 명시적 새 대화/폐기와 단순 화면 이탈을 구분한다.

### 3. 무료3회·유료 호출 안전장치 처리안

- 한도는 work별이 아니라 비회원 세션의 여러 대화를 합산한다. 새 대화·동시 요청·동일 키 재전송으로3회를 추가 지급하지 않는다. cookie 삭제/다른 브라우저를 동일인으로 완벽히 식별한다고 보장하지 않으며 보조 요청 제한·서비스 전체 차단을 별도로 설계한다.
- API 접수 때 세션 한도를 transaction으로 예약하고 요청 식별자와 연결한다. 동일 요청은 같은 revision·예약을 반환하며 추가 차감/생성을 하지 않는다. 유료 dispatch 전 전체 BudgetLedger와 전역 이미지2 제한도 적용한다.
- 한도 계산의 기술 초안은 `예약 중 + dispatch/결과불명 + 확정 사용 ≤ 3`이다. 명확한 미전송/무과금 거절은 예약을 해제할 수 있고, 전송 여부 불명은 유지한다. 응답 실패의 반환 조건은 dispatch 증거·비용 예약과 함께 상세 명세/테스트에 적는다. 성공 수만 세어 실패/동시 요청으로 과금이 무제한 반복되는 구조를 피한다.
- 3회 도달 후에도 이미 만든 시안 선택·목업·로그인·저장/구매를 제공한다. 로그인하면 무료 횟수가 다시 생긴다는 정책은 아직 정하지 않았으므로 UI에서 약속하지 않는다.
- SDK 유료 재시도0·unknown 자동 재전송 금지·원래 결과/영수증 복구를 유지한다. 개발 검증 총 승인USD100/초기USD5와 모델·가격 검토 조건은 바꾸지 않는다. 이 초안 작성으로 실제 유료 호출을 실행하지 않는다.

### 4. 로그인 후 작업 인계 처리안

- 저장/구매 버튼은 현재 선택 revision·대화·반환 위치와 원래 의도를 서버가 검증할 수 있는 인계 정보로 보존한 뒤 OAuth로 이동한다. 임의 외부 redirect·URL에 비밀 token 노출을 허용하지 않는다.
- OAuth 성공 시 세션의 비회원 작업 소유권을 확인하고 로그인 사용자에게 한 번 귀속한다. 비회원 상태를 단순히 현재 로그인 계정 ID로 치환하지 않는다. 중복 callback/탭·다른 계정 경합·만료·소유권 불일치를 처리한다.
- 원래 선택한 결과와 저장/구매 의도로 복귀한다. 로그인이나 인계만으로 디자인을 재생성·구매 확정·앨범 개설하지 않는다. 기존 세션 초기화가 비회원 인계 대상을 먼저 지우지 않도록 수명주기를 설계한다.
- 새로고침/네트워크 오류 후 인계와 저장 요청은 같은 결과를 반환한다. 회원의 기존 디자인/사진첩은 비회원 대화와 격리한다.

### 5. 구매 완료와 전용 앨범 자동 개설 처리안

- 디자인, 구매/주문, 구매한 굿즈, 앨범 권한을 구분한다. 저장된 디자인은 구매 없이 존재할 수 있다. 같은 디자인의 재구매/수량 처리가 가능하므로 현 `GoodsDesign.album_id` 하나를 모든 구매의 대응 관계로 고정하지 않는다.
- 서버가 검증한 구매 완료만 앨범 개설 권한을 만든다. 브라우저의 성공 화면/클라이언트 flag·디자인 저장·파일럿의 제작확정/메일 접수를 결제 완료의 근거로 사용하지 않는다.
- 구매 식별자와 확정된 앨범 권한 단위에 unique/idempotency 제약을 두고 전용 빈 앨범과 연결을 영속화한다. 동일 완료 통지/재시도는 동일 앨범을 반환한다. 미결제·실패에는 개설하지 않는다.
- DB 반영 실패/완료 이벤트 중복에 대비해 구매 확인과 outbox/개설 job을 원자적으로 기록하는 경계를 설계한다. 사용자는 필요 시 ‘앨범 준비 중’을 거쳐 이미 연결된 사진 채우기 화면으로 이동하며 기존 앨범 선택 단계는 없다.
- 구매 이후 앨범 생성뿐 아니라 해당 신규 앨범의 업로드 예약·complete·생성 dispatch에도 구매 권한을 검증한다. 단순히 ‘새 앨범’ 버튼만 숨기는 방식으로 대체하지 않는다.
- 기존 독립 앨범·업로드 예약·진행run·기존 수동 연결은 소급 차단/삭제/재작성하지 않는다. 새 구매 기반 경로와 legacy 데이터 경로를 명시적으로 구분한다. 이전 API의 무제한 신규 개설을 새 경로에서 우회 수단으로 남기지 않는다.
- 주문/결제 제공자, 상품별 장수·기간·수량별 권한 대응, 취소/환불 후 앨범 접근은 구매 묶음 상세 설계 대상이다. 참고 문서의 기본20/확장50·연장·NFC 등은 이번 초안에서 공통계약의 실행 한도로 일괄 이식하지 않는다. 실제 PG 연결/실거래·외부 제작 주문·운영 배포는 별도 실행 범위다.

### 6. 현재 구현과 달라지는 경계 및 인수 기준

| 현재 경계 | 다음 작업 |
|---|---|
| 전역 `AuthGate` | 굿즈 공개 진입/선택 로그인과 기존 회원 전용 화면 분리 |
| 사용자 FK 소유 work·회원 전용 미디어 | 비회원 소유권·후속 귀속·정리·비공개 미디어 접근 설계 |
| 사진1장 필수 service/provider/prompt | 설명만 생성·선택 첨부·선택 시안 수정 분기와 입력 snapshot |
| 이탈 시 폐기되는 단계형 workspace | 요청/결과 대화·첨부 확인·새로고침/OAuth 복원·선택 이력 |
| 회원 저장/기존 published 앨범 수동 연결 | 로그인 후 저장/구매 분기·구매 완료 후 전용 빈 앨범 자동 개설 |
| 독립 앨범 생성 API | 새 구매 권한 경로와 기존 데이터 호환의 명시적 분리 |

필수 인수 시나리오: 사진 없는 첫 생성, 사진 첨부/실패 보존, 이전 시안 분기 수정, 새 대화를 포함한3회 제한과 동시4번째 거절, 동일 키 재접수 차감1회, unknown 보존, OAuth 왕복/중복 인계/다른 계정 차단, 로그인 후 저장과 구매 의도 복귀, 저장만으로 앨범0개, 미결제 개설0개, 동일 구매 완료 중복에도 앨범1개, 개설 중단 후 같은 앨범으로 복구, 직접 API를 통한 구매 전 업로드/생성 우회 차단, 기존 회원·예약·진행run 회귀, 모바일 키보드·뒤로가기·복귀·만료 미디어·첨부 메모리 정리.

근거는 [기능요구명세서0절](기능요구명세서.md#0-최신-제품-방향--2026-10-22-사용자-확정)과 [개발운영 최신 계획](개발운영.md#현재-진행-계획--ui-업그레이드-준비-2026-10-22)의 사용자 결정·지정 TASK-002/003 조사다. 비회원/실구매의 전체 변경은 미실행이며, v1.3 테스트 경로의 API/DTO/샘플·migration만 별도 구현했다. 외부 코드 이식·실제 구매/유료AI·운영 배포는 수행하지 않았다.
