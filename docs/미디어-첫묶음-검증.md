# 미디어 첫 묶음 Task 3·Task 4·G1 — 2026-10-19

사용자가 승인한 첫 병렬 묶음의 로컬 구현/검증 기록이다. 기존 Task2 쌍 업로드 기반 위에서 작업했다. 운영 배포·운영 migration·QA 변경·실제 유료 API 호출은 하지 않았다. 기존 moriai 코드 이식이나 신규 의존성 추가 없음.

## 구현 범위

| 범위 | 구현 |
|---|---|
| Task3 앨범 프론트 | JPEG/PNG 보수적12MP 경계 유지, 단일 bitmap 본문2048/85·썸네일480/80, 본문1,000,000bytes 목표,0.8배 재축소·1024 하한, 정확3:4 유지, 쌍 파일/해시/예약/PUT 상태 재시도 보존·취소/자원 정리 |
| Task4 서버 | 새 예약 정규화v3/reuse1, 실제 WebP 구조/디코딩/크기/방향/색상/해시 검증 후 재사용 또는 메타데이터 정리, 썸네일 비교/부분 재생성, 원래 크기 기록, immutable 저장 뒤 ready/임시 정리 |
| G1 굿즈 서버 | 기존v2 codec으로 JPEG/PNG/WebP/HEIF 실제 파일 검사,20MiB/40MP·2048/85, body 수신 전 active1·waiting2·5초 제한, 취소 정리, 소유자 전용 WebP 미리보기·원인별 오류 |

새 업로드 설정은 NORMALIZATION_VERSION3·85·2048·1,000,000이며 기존 환경 파일을 변경하지 않았다. 기존 예약에 저장된 v1/v2 설정·run snapshot을 다시 쓰지 않는다. v2 변환기는 기존 normalize.py와 byte-identical한 normalize_v2.py로 보존한다. 새 버전 입력 hash와 정리된 출력 hash는 구분한다.

본문 재사용은 디코딩 검사를 생략하는 기능이 아니다. 알려진 sRGB ICC는 hash로 식별한다. EXIF/GPS/XMP/불필요 외부 청크 정리와 압축 픽셀 재인코딩을 분리하며, 내부 미소비 바이트가 전혀 없어야 한다는 요구는 추가하지 않았다. 낯선 ICC·회전/축소 필요·기존 미지원 HDR은 기존 검증/정규화 경로로 처리한다.

굿즈는 서버 G1만 구현했다. 프론트 HEIC 선택·고해상도 축소·오류 문구 연결(G2)은 아직 없다. 굿즈 출력 상한은20MiB로 유지해 앨범1MB 목표를 신규 거부 조건으로 추가하지 않았다. v2 재사용으로 굿즈에서 사용하지 않는 썸네일도 생성하는 비용은 남는다.

## 검증 및 발견한 문제

- Task3: 초기7개 전처리 실패·쌍 전송2개 실패·hook 실패를 확인 후 구현. 최종 scoped 테스트32개 및 TypeScript 통과.
- Task4: 초기8개 미구현 실패 후 구현. HDR XMP가 지워져 수용되는 회귀를 추가로 발견해 기존 HDR 거부 경로로 수정했다. 전체 미디어198개+하위검사10개, 신규 통합3개 통과.
- G1: 초기 missing module/GET 실패 이후 구현. HEIF fixture는 Image.Exif 객체 대신 serialized EXIF로 실제 irot를 생성하도록 바로잡았다. 최종 굿즈 HTTP·media·공통 child 검사32개와 migration 왕복/schema check 통과.
- 독립 검토: Task3/G1 검토 후 통합 검토 수행. Task4의 큰 픽셀 썸네일 DecompressionBombError가 정상 본문도 거부하는 문제를 발견, 썸네일만 재생성하도록 수정하고 미디어20개 재실행 통과·재검토 완료.
- 최종 통합 검토: 정확3:4 사진의 1MB 재축소가 정수 반올림으로 비율을 깨뜨리는 문제를 발견했다. 프론트3k×4k 계산으로 수정하고 일반/EXIF 회전 입력 회귀 검사32개 통과·재검토 완료.
- 최종 frontend Docker target 빌드 성공. npm typecheck/Vite build 및 Dockerfile의 Node 회귀 검사 전체가 포함된다. 전용 태그 `mori-ai:batch1-front-check`를 사용하고 기존 QA 태그를 덮어쓰지 않았다.
- 공통 설정 검사: 최초3개 실패 후 normalization_version 검증/기본값 구현,12개 통과.
- 전체 backend: **928 passed, 1 failed, 10 subtests passed (431.63s)**. 유일한 실패는 이전 Task2의 잘못된 썸네일 전체 거부 기대값이다. 제품 코드는 변경하지 않고 v2는 거부·v3는 정상 본문 유지/썸네일 재생성으로 검사를 나눴다. 수정 후 쌍 업로드+준비 미디어 통합 **12 passed (6.93s)**, 독립 검토 통과. 전체 모음은 다시 실행하지 않았으며 최초 전체 실패와 수정 후 범위 재검증을 구분한다.
- 전체 검사에는 기존 생성/진행 작업 복구, 임시 source retirement, R2 경계·late PUT, 사용자 격리 검사가 포함됐다. R2는 가짜 저장소 경계이며 실제 운영 R2 연동 검증을 의미하지 않는다.
- 최종 JSON 파싱·diff check 및 frozen v2 파일 동일성 확인 통과. 테스트별 임시 PostgreSQL project/volume은 종료 후 제거됐다.

## 실제 브라우저 관측

[관측 JSON](미디어-첫묶음-browser.json)은 합성 fixture 기반 결과다.

- Chromium147에서 EXIF/GPS JPEG·PNG와 일반PNG3개의 본문/썸네일 생성. 서버에서 모두 sanitize_then_reuse로 처리했다. ICC/메타데이터 정리 전후 디코딩 픽셀은 동일했다.
- EXIF1~8의3000×2000 합성 사진이2048 긴 변으로 축소되고 방향별 색상 위치가 Pillow 기준과 일치했다(표본 채널 차이≤1).
- 투명 고밀도PNG는900×600 본문346556bytes,480×320 썸네일80378bytes로 처리됐고 서버 재사용 전후 alpha 포함 픽셀은 동일했다. 작고 압축 효율이 좋은 PNG는 합산 절감 조건에 따라 원본 fallback을 유지했다.
- 정확3:4 고밀도3000×4000 JPEG는 재축소 후981×1308·739336bytes, 썸네일360×480로 출력됐다. 서버 원래 크기 힌트 검증 및 본문 재사용 통과. 실제 압축 크기는 랜덤 합성 fixture별로 달라진다.
- 미지원 ICC/XMP/text 입력의 원본 fallback 유지 확인. WebKit 로컬 프로세스가 멈춰 중단했으며 성공으로 기록하지 않는다. 실제 iPhone과 실제 운영 실패 사진은 검증하지 않았다.
