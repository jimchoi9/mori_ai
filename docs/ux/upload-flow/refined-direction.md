# 카카오톡식 전송의 친숙함과 간결화

2026-10-28 · 사용자 반응을 반영한 제안/모형 · 제품 미적용

## 최신 반응과 중간안

사용자는 최소 문구안이 너무 허전하고 어색하며, 이전 카카오톡식의 안내 말풍선이 익숙함을 만든 것 같다고 구체화했다. 이전 안은 불필요한 문구가 많다고도 했다. 따라서 **안내 말풍선 하나는 남기고 반복 설명을 줄이는 중간안**을 새 기준으로 삼는다. 아래 최소 문구 제안은 직전 탐색 이력이며, 안내 말풍선을 모두 제거한다는 부분은 최신 방향에서 수정한다.

`http://192.168.0.120:18192/balanced` — 중간안 / 이전 카톡식 / 최소 문구안. 새 첫 화면에서 왼쪽의 `이 앨범에 사진을 골라 보내주세요.` 한 문장과 하단 사진 추가를 보여준다. 보낸 사진은 오른쪽의 짧은 말풍선 형태 묶음으로 남긴다. 큰 제목·화면 동작 설명·중복 장수·상시 화질 안내는 넣지 않는다. 상태/오류/필요한 버튼명은 유지한다.

안내 유지 기간은 사용자에게 ‘첫 전송 전까지만 / 전송 후에도 유지’를 질문했다. 현재 모형 기본은 비어 있는 앨범의 첫 전송 전까지이며, 전송을 시작하면 사진 묶음이 그 자리를 채운다. 상단 비교용 체크로 전송 후 유지도 조작해 볼 수 있다. 질문의 미응답을 정책 승인으로 해석하지 않으며 실제 서비스에는 아직 적용하지 않는다. 그 외 여백·색·모서리·사진 미리보기는 기존 Mori 스타일과 모바일 조작 영역을 따라 일상적 설계 판단으로 정리한다.

## 받은 반응

사용자는 ‘한 화면·보내기 한 번’은 선호하지 않으며 바로 전송과 카카오톡식을 비교 중이다. 바로 전송은 더 간결하게 보이지만 카카오톡식은 익숙하고 ‘업로드’의 거부감이 덜하며 사진을 전송하는 느낌이라고 말했다. 필요한 텍스트만 남기도록 요청했다.

이 반응을 세 가지 가설로 해석한다. 사용자의 심리 원인을 직접 측정한 결과는 아니다.

- **익숙한 행동:** 사진 추가→첨부 미리보기→보내기→보낸 묶음이 남는 흐름을 이미 알고 있어 다음 행동을 추측하는 부담이 적을 수 있다.
- **전송 시점의 통제:** 사진을 고르는 일과 보내는 일을 구분할 수 있다. ‘선택을 마치자마자 전송’은 익숙해지기 전까지 예상과 다를 수 있다.
- **작업의 인상:** 같은 보내기 버튼이 있어도 큰 제목·등록 안내·관리 상태가 많은 화면과 하단 첨부 영역에서 사진을 보내는 화면은 다르게 느껴질 수 있다. 본 사용자 반응에서는 버튼 수만으로 차이를 설명할 수 없다.

이는 [NN/G의 mental model 원칙](https://www.nngroup.com/articles/mental-models/), [사용자 통제 원칙](https://www.nngroup.com/articles/user-control-and-freedom/), [클릭 수만으로 평가하기 어려운 이유](https://www.nngroup.com/articles/3-click-rule/)와 부합하는 해석이다. 이 문헌들은 Mori의 업로드 선호나 카카오톡식의 직접 비교 우위를 입증한 실험이 아니다. 특히 클릭 수 자료의 주된 범위는 탐색/정보구조다.

## 비슷하게 느끼는 사람이 더 많은가

현재 선호 비율은 모른다. 카카오톡식에 익숙한 Mori 고객에게 유효한 가설이지만, 메신저 이용자 수를 이 업로드 방식의 선호율로 바꿔 말할 수 없다. 자동 저장에 익숙한 사용자는 바로 전송을 선호할 가능성도 있다. 나이·디지털 숙련도로 선호를 단정하지 않는다.

소수의 실제 예상 고객에게 설명 없이 같은 사진 묶음을 담도록 하고 두 안의 순서를 교차해 먼저 문제를 찾는다. ‘어느 쪽이 예쁜가’만 묻지 않고 처음 해야 할 일을 찾는지, 언제 전송됐다고 생각하는지, 잘못 고른 사진을 고칠 수 있는지, 다시 쓸 때 어느 쪽을 고르는지 관찰한다. 소수 관찰은 다수의 선호를 추정하는 통계조사가 아니다. 이 관찰을 시작 전의 추가 질문/승인 절차로 만들지 않는다.

## 간결한 카카오톡식 제안

익숙한 하단 첨부/보내기/전송 묶음을 유지하고 읽어야 할 문구를 줄인다. 가짜 상담자·자동 답장·입력할 수 없는 채팅 입력창을 추가하지 않는다. 실제 저장·권한·최적화 정책을 숨기거나 바꾸는 방식으로 가볍게 보이게 만들지 않는다.

| 상태 | 남길 내용 | 추가 조작 |
|---|---|---|
| 처음 | 앨범 이름, 정원, `＋ 사진` | 사진 선택 |
| 선택 | 사진 미리보기, `12장 보내기` | 사진을 누르면 전체 선택 목록. 추가/해제는 선택적 |
| 전송 | 같은 사진 묶음, 실제 저장 수 `6/12 저장` | 정상 흐름에서 없음 |
| 완료 | `12장 저장 완료`와 사진 묶음 | 정원 미만일 때만 사진 추가. 완료 확인 없음 |
| 오류 | `11장 저장 · 1장 실패`, `1장 다시 보내기` | 자동 복구 소진 후 남은 항목만 |

제거: 큰 환영 제목, 안내 말풍선, ‘보낸 사진이 묶음으로 남아요’ 같은 화면 설명, 선택 장수의 반복, 화질 자동 안내의 상시 노출, 사진마다 반복되는 정상 상태 문구, ‘묶음 보기/접기’ 텍스트 버튼. 사진을 누르는 조작의 접근성 이름은 유지한다. 첫 진입의 사진 추가와 보내기는 글자를 남겨 기능을 알 수 있게 한다.

정원은 채워야 하는 목표가 아니다. 서버 저장 확인 전 완료로 표시하지 않는다. 전송 중에만 `저장이 끝날 때까지 열어두세요`를 남긴다. 완료 후 이탈 가능성을 실제 사용자가 이해하지 못하면 그때 짧은 안내를 보완한다. 문구 수를 줄이는 일을 오류 은폐·모호한 아이콘·재시도 책임 전가로 바꾸지 않는다.

모바일에서는 얇은 간격, 동일한 사진 모서리/크기, 하단 첨부와 작은 보내기 버튼, 사진 중심의 전송 묶음으로 정돈한다. 정상 상태의 장식/연출·튜토리얼·화질 옵션은 추가하지 않는다. 사진 비율은 미리보기에서만 정돈하며 실제 이미지를 새로 자르거나 AI 변환하지 않는다.

## 비교 주소와 구현 경계

`http://192.168.0.120:18192/refined` — 간결한 카톡식 / 바로 전송 / 이전 카톡식. 같은 Wi-Fi, Mac/프로세스 실행 필요. IP 변경 시 재실행한다. 기존 `/` 비교안은 보존했다. `refined-upload-flows.html`과 `serve_browser_preview.py`만으로 합성 자료를 표시하며 실제 파일 업로드/로그인/API/AI/메일이 없다. 모의 속도·저장 수는 서버 성능 검증이 아니다.

현재 추천은 간결한 카카오톡식을 다음 비교의 기준으로 삼는 것이다. 사용자의 최종 채택이나 실제 서비스 구현 완료를 뜻하지 않는다. 기존 공통계약 v1.16·20장·저장/관리목록 범위·모듈 경계는 그대로다. 자동 선별·글/앨범 자동 완성·영상·AI3:4·완성 후 사진 변경은 추가하지 않았다.
