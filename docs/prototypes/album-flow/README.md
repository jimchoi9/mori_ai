# Mori 앨범 흐름 체험 목업

## 5차 목업 — 하단 고정·로그인 디자인

사진 추가는 빈 앨범부터 공통 하단 바 하나만 사용한다. 모바일은 viewport fixed, 데스크톱 모형은 스크롤 영역 밖의 폰 하단이다. 편집 시 같은 자리에 완료 버튼을 둔다. 로그인 제목을 시각적으로 제거하고 로고/자체 제작 앨범 SVG/소셜 버튼을 배치했다. 실제 제품 LoginView에도 같은 SVG와 배치를 적용했다. 제품 ContentManager는 기존 fixed 바를 유지한다. 목업의 중앙 버튼/목록 끝 sticky 구조를 수정한 것이다.

최신 링크: `http://localhost:18204/?v=6` / `http://192.168.0.40:18204/?v=6`. 390×844 빈/50장 처음·끝/편집에서footer bottom844,320×740에서740,데스크톱폰하단과footer1px차이(테두리)확인. 실제제품로그인390×844·320×568에서이미지로딩/가로넘침0/두버튼화면내표시. 실제휴대폰터치/키보드는별도다. 아래는이전차수이력이다.

## 4차 목업 — 로그인·등록 문구와 정렬 복원

로그인/등록의 중복 제목·감성 설명을 제거하고 필수동의·등록계정·등록버튼만 남겼다. 직접배치 순서를 기억하고 촬영순→직접배치로 복원한다. 삭제는 제외, 새 사진은 뒤로 붙인다. 목업은 탭 메모리라 새로고침하면 초기화되고, 함께 구현한 제품은 서버에 저장한다. 새 링크는 `http://localhost:18204/?v=5` / `http://192.168.0.40:18204/?v=5`. 아래는 이전차수이력이다.

## 3차 목업 — 불필요한 문구 제거·드래그 복구

- 사용자 피드백: 기존 드래그 편집을 화살표로 바꾼 것은 개선이 아니며, 의미 없는 제목·슬로건·상시 설명을 제거한다. 기존 제품의 드래그 편집은 그대로 보존하고 목업만 수정했다.
- 상단은 `내 앨범`, 사진 수, 계정 버튼으로 정리했다. `우리의 작은 순간들`, `나를 위한 작은 기록`, `언제든 수정할 수 있어요`, 상시 날짜/정렬 설명을 제거했다.
- `촬영순`은 실제 메뉴 버튼이다. 촬영 시간순 복구 또는 직접 배치를 선택한다. 편집 중 사진 옆 손잡이에서만 드래그하며 가장자리 자동 스크롤과 키보드 위/아래 이동을 지원한다. 작은 썸네일+글 행, 삭제와 하단 편집 완료는 유지한다.
- 기존 상시 완료 패널은 제거했다. 업로드 중에는 진행률, 완료 후에는 `N장 업로드 완료` 알림을2.8초 표시하고 내용까지 지운다. 사진 수와 목록은 남는다.
- 검증: Chrome 실제 포인터 드래그로 첫 사진→세 번째/직접 배치 전환, 촬영순 복구 확인. 완료 알림 표시2802ms 뒤 내용/표시 제거, 50장 마지막 글 수정 보존,320/390폭 가로 넘침0,입력16px,콘솔오류0. browse 도구의 CDP 포인터 명령은 허용 목록 밖이어서 CUA의 정식 drag API로 검증했다. 실제 휴대폰 터치/키보드는 미검증이다.
- 모바일 접속 실패 조사: 안내했던192.168.0.43이 현재192.168.0.40으로 변경됐다. 서버는18204/all interfaces에서 계속 실행 중이며 Mac에서 새LAN주소 HTTP200. 같은Wi-Fi 실제휴대폰 접속은 사용자 확인이 필요하다. 새 주소는 `http://192.168.0.40:18204/?v=4`, Mac은 `http://localhost:18204/?v=4`.
- 이번 수정 파일은 이 목업의 HTML/CSS/JS/README와 작업기록이다. 제품 UI·권한·계약 변경/서버 반영/AI호출 없음. 아래2차/초기 기록은 당시 이력이다.

## 2차 목업 — 사용자 스크린샷 피드백 반영

- 사진 추가와 앨범에 담기 버튼이 동시에 나타나는 구조를 제거했다. `사진 추가` → 팝업에서 선택/해제 → `N장 선택 확인` → 즉시 업로드 시뮬레이션이다. 확인 전에 팝업을 닫으면 전송하지 않는다.
- 선택 전/중 상태는 팝업에만 표시한다. 확인 버튼 근처에 바로 업로드된다는 안내, 선택 장수, 정원 초과 안내를 표시한다. 내 파일도 팝업의 선택 확인을 거친다.
- 앨범에는 저장된 사진 수와 `업로드 중 k/N`/`업로드 완료`를 구분한다. 완료된 사진만 목록에 넣는다. 별도 앨범 담기 버튼과 대기 사진 묶음은 없다.
- 큰 세로 카드를84px 썸네일+글의 가로 행으로 변경했다.320폭은64px, 입력 글자16px, 개별 사진 클릭 확대는 유지한다. 편집 중 화살표로 순서 변경, 삭제, 하단 편집 완료를 제공한다.
- 직접 검증:9장 확인 직후 업로드중/저장0→저장9와 완료안내, 선택취소 시9장유지/추가전송0,50장 편집 행127px·390폭 완료버튼 bottom844,320폭 overflow0.49장에서9장선택 시8장초과로 확인차단.합성JPG도 팝업에서확인전49장유지/선택1→확인후업로드 시작을 확인했다. 제품 API/저장은 여전히 연결하지 않는다.
- 아래 초기 체험 순서의 별도 `앨범에 담기`와 큰 카드 설명은 1차 이력이다. 현재는 이 절을 우선한다.

사용자가 설명만으로 통합 화면을 판단하기 어렵다고 요청해 만든 독립 목업이다. 제품 프론트/서버에 연결하지 않는다. 외부 패키지·폰트·이미지 요청 없이 HTML/CSS/JS와 자체 SVG 샘플로 실행한다.

## 열기

```bash
python3 -m http.server 18204 --bind 0.0.0.0 --directory docs/prototypes/album-flow
```

Mac: http://localhost:18204/?v=4

같은 Wi-Fi 휴대폰: `http://<Mac의 현재 LAN IP>:18204`. 2026-11-02 최신 확인 IP는 `192.168.0.40`이다(처음 안내한 `.43`에서 변경). Mac/서버가 켜져 있어야 하며 IP는 바뀔 수 있다. 서버는 이 폴더만 제공한다. `index.html`을 파일로 직접 열어도 동작한다.

## 체험 순서

1. 제안 모드에서 선물 QR 시작 → 가짜 로그인 → 첫 이용 동의 → 등록 확인 → 바로 앨범 진입.
2. `사진 추가` → 샘플 선택 → 선택/선택 해제 → `N장 선택 확인` → 바로 업로드 시뮬레이션.
3. 같은 화면에서 사진 크게 보기, 사진·글 편집, 손잡이 드래그 순서 변경, 삭제, 촬영순 메뉴로 정렬 복구.
4. `샘플 50장 체험` → 마지막 사진 글 수정 → 하단 `편집 마치기`.
5. 계정 메뉴의 바깥 클릭/Escape 닫힘.
6. 비교 선택창을 현재 모드로 바꾸어 등록 뒤 `사진 추가하기`를 한 번 더 누르는 차이를 확인.
7. `등록된 선물 QR 재방문`으로 현재는 등록 완료 화면, 제안은 앨범 직접 진입을 비교.

현재 모드는 **현재 선물 진입의 핵심 단계/문구를 재현**한다. 기존 UI의 픽셀 단위 복제나 실제 인증이 아니다. 앨범 화면은 두 모드 모두 제안 UI다. `내 책장`은 목업의 단일 앨범으로 이어지며 전체 책장 UI는 만들지 않았다. 소셜 계정 변경도 가짜 이름 변경이다.

## 실제 구현과 구분

- 로그인/등록/동의/진행률/저장은 메모리 시뮬레이션. 서버·OAuth·AI·실제 결제·QR 토큰 처리가 없다.
- 샘플 글과 시간은 고정된 예시다. 사진을 분석하거나 EXIF를 읽지 않는다. 내 파일은 JPG/PNG/WebP 미리보기와 파일 수정일만 사용한다. HEIC는 제품의 기존 코덱 검증 범위이며 이 목업에서 처리하지 않는다.
- 내 사진은 Object URL로만 표시한다. 전송·localStorage 저장이 없고 새로고침하면 사라진다.
- 초기 반응형 점검에서 모바일 sticky 버튼의 부모 overflow 문제를 찾아 보완했다. 데스크톱 Chromium 모바일 폭 검사이며 실제 iOS/Android 키보드의 확대 문제를 해결했다는 증거는 아니다.
- 사진 교체·실제 업로드 장애/복귀·계정 권한 처리는 제품에서 유지해야 하는 요구다. 이 목업에서는 선택/삭제/글/순서 동선만 체험한다. 선택 초과 시 사진을 보존하고 50장 이하로 줄여야 담을 수 있다.

## 선물 중간 화면 조사

- `frontend/src/features/goods/GiftRegistration.tsx`: available 상태의 `내 앨범 만들기`가 gift/claim을 호출한다. registered 상태에서 화면을 유지한 채 `사진 추가하기`/`내 책장` 링크를 표시한다. 이미 등록한 계정이 QR을 다시 열어도 이 상태를 보여준다.
- `backend/goods_design/delivery/gifts.py`: 최초 명시적 claim은 album.owner_id 변경·management_pending 해제·claimed_by 기록을 수행한다. 로그인이나 QR 열기와 달리 실제 관리 계정을 확정한다. 이 의사는 자동 로그인만으로 대체하지 않는 제안이다.
- `frontend/src/features/auth/AuthGate.tsx`: 첫 이용 동의 버튼은 `동의하고 책장으로`라고 쓰여 있지만 children은 현재 경로를 따른다. 선물 QR에서는 다음이 선물 등록이다. 제안 목업은 목적에 맞게 문구를 바꾼다.
- 등록 완료 후 별도 이동 화면은 제거 후보, 최초 관리계정 확인은 유지 후보다. 사용자 승인 전 제품 권한/라우팅은 수정하지 않았다.

## 최신: 장소·행동 중심 비교 — 2026-11-02

사용자가 관계 재사용 제외에 동의했다. 같은 주소 `caption-context.html?v=2`에서 `사진만 참고` / `지역 단서 참고`로 비교한다. 다른 사진의 사용자 글·관계·행동은 입력에서 제외했다. 예시는 ‘기장의 식당에서 함께 만두를 나눠 먹었다’, 음식만 보이는 경우 ‘기장의 식당 테이블에 만두 한 접시가 놓여 있다’이다. 얼굴 저장/기억/식별은 없다.
이 문장들은 직접 작성한 기대 예시다. 지역명도 합성 fixture이며 GPS조회/실제사진분석/AI호출은 하지 않는다. selector25검사, 합성7상황, JS문법 검사 통과. 브라우저에서 지역 전환과 음식만 있는 경우를 확인했다. 제품에 반영된 기능으로 해석하지 않는다.
