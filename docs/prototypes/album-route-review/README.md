# 앨범 카드의 감상·관리 동선 체험

사용자는 최종 삭제 확인으로 ‘삭제’ 직접 입력을 확정했지만, 더보기의 설정 단일 항목→설정의 삭제 단일 항목→확인창이라는 빈 단계를 거절했다. 이 체험은 최종 입력 게이트를 유지하면서 앨범별 진입을 표지→감상 / 앨범 관리→추가·편집·이름 수정·삭제로 묶는 후보를 보여준다. 배치·문구·동선은 사용자 확인 전이다.

내 앨범 카드의 더보기/별도 설정을 없앴다. 관리 상단 오른쪽의 조용한 앨범 삭제 버튼에서 입력 확인창을 바로 연다. 50장 목록 아래까지 스크롤해야 하는 삭제 위치는 사용하지 않았다. 복귀100×48px과 삭제80×48px을 분리하며 제목은 일반 글자/연필만 수정 트리거다. 입력 조건 전 확정 비활성, Enter 비삭제, 취소 우선 포커스, 다시 열면 입력 초기화, 현재 제목/사진 수와 연결된 굿즈의 새 감상 영향 표시를 유지한다.

감상은 기존 book.js/page-flip.js/createBookPhotos로 열고 별도 내비게이션을 두지 않는다. 브라우저 뒤로가기로 예시 목록/관리로 돌아온다. 새 앨범/계정/굿즈 진입은 제품에서 유지하며, 이 앨범별 동선 체험에서는 생략했다.

모든 표지·사진은 개인 자료 없는 도형 예시다. 이름/글귀/선택 사진은 탭 메모리에서만 바뀐다. 예시 사진 선택창은 실제 휴대폰 기본 선택기가 아니다. 사진 추가/글귀 편집/이름 수정은 그룹을 체험하기 위한 모형이며 실제 업로드·AI·저장/50장 한도·순서 변경·권한·복구를 다시 검증한 것이 아니다. 마지막 삭제 버튼은 예시 앨범만 숨기고 초기화/새로고침으로 돌아온다. 제품 휴지통/복구 기능으로 약속하지 않는다.

소스 index/preview CSS/JS를 ignored output/album-route-review로 복사했다. 기존 합성 표지3장/책 라이브러리/현재 관리와 제목 CSS를 사용한다. album-home-review/server.py의 특정 LAN 바인딩·고정 파일 목록·개인 prefix·no-store·CSP connect none으로 제공한다. 실제 API·사진·앨범·DB·AI·메일·서비스 runtime에는 연결하거나 변경하지 않는다.
