상태: 사용자 체험 후 A ‘관리에서 바로 복사’ 채택. 아래 B 추천은 비교 당시 제안 이력이다. 실제 구현은 공통v1.35를 따르며 운영 미반영이다.
작업 브랜치 `feat/album-share-link-review`, 기준 `8ef7ede007edee1689278fbac3b29b5ed9090d1c`.

## 목표와 추천

일반 앨범도 구매 없이 특정 앨범의 익명 감상 링크를 직접 만들고 다시 꺼낼 수 있게 한다. 받은 사람은 로그인 없이 그 앨범만 감상한다. 앨범 소유자의 다른 앨범이나 수정 권한은 공개하지 않는다. 같은 전체 주소를 메신저와 NFC에 사용한다.

**추천은 B: 앨범 관리의 ‘공유’ → 작은 패널이다.** 첫 공유의 공개 범위를 짧게 알리고 발급 결과와 복사를 확인할 수 있다. 목록의 감상 중심 구조와 뷰어를 유지하며, 별도 설정·완료 페이지를 만들지 않는다. 반복 공유의 빠르기는 A가 우세하다. 아래 탭 수는 공통 시작점인 내 앨범 목록에서 복사 완료까지의 정상 경로이며 사용성 실험 점수가 아니다.

| 안 | 첫 공유 | 다시 복사 | 이점 | 판단할 부분 |
|---|---|---|---|---|
| A 관리에서 바로 복사 | 관리 → 복사, 2회 | 2회 | 가장 빠름 | 첫 발급을 모른 채 공개될 수 있고, 비동기 발급 직후 복사는 기기에서 실패할 수 있음 |
| B 관리의 공유 패널 | 관리 → 공유 → 만들기 → 복사, 4회 | 3회 | 공개 범위·준비 상태·복구를 한곳에서 확인 | 첫 공유에 한 번 더 누르는 느낌이 부담스럽지 않은지 |
| C 목록에서 바로 공유 | 공유 → 만들기 → 복사, 3회 | 2회 | 관리 화면을 거치지 않음 | 카드의 감상·관리·공유 분기가 늘어남 |

B에서 기존 링크는 ‘만들기’를 다시 누르지 않는다. 발급 성공이 복사 성공인 것처럼 표시하지 않는다. 시스템 공유가 가능한 브라우저에서는 ‘다른 앱으로 보내기’를 함께 제공하며, 취소하면 링크는 유지한다. ‘NFC에도 같은 링크를 사용해요’만 안내하고 별도 NFC 주소를 만들지 않는다. 주소 입력란은 직접 복사할 때만 열며 자동으로 키보드를 띄우지 않는다. 공유 일시 중지는 ‘링크 관리’에 접고, 같은 NFC도 멈춘다는 안내 후 끄며, 다시 켜면 주소를 유지한다.

빈 앨범/사진 저장 중에도 주소를 준비할 수 있도록 비교 화면을 만들었다. 받은 사람에게는 ‘추억을 담고 있어요’가 보이고 사진 저장 뒤 같은 주소가 열린다. 이 정책과 패널의 실제 느낌은 사용자 판단 대상이다. 글귀가 미완료여도 저장된 사진 48장을 모두 감상하며 해당 글귀만 비운다. 아직 저장되지 않은 수정 내용은 먼저 저장을 확인하고 실패하면 발급하지 않는다.

독립 두 번째 검토도 B를 권고했지만 이는 현재 사용자 선호와 화면 구조에 대한 설계 의견이다. 실제 고객 사용성 검증이나 사용자의 최종 선택으로 표현하지 않는다.

## 체험 방법

현재 LAN 접속 주소는 gitignore된 `output/album-share-link-review/access.json`에 있다. 원본 checkout, 기존18187/18188, 운영 서비스는 변경하지 않았다. 같은 Wi-Fi와 Mac 실행이 필요하다. HTTPS 기본18231, HTTP18230. 발급한 체험 링크도 이 LAN 안에서만 동작한다. 인증서 경고를 무시하지 않는다. 현재 재사용 중인 로컬 인증서는 2026-11-07 14:07:41 UTC 만료이며 키는 복사·기록하지 않았다.

1. ‘첫 공유’에서 A/B/C를 차례로 눌러 복사까지 비교한다. A/B는 ‘앨범 관리’, C는 목록의 ‘공유’를 사용한다.
2. 이미 만든 링크를 다시 복사해 불필요한 단계를 확인한다.
3. ‘체험용 내용 바꿔보기’에서 받은 사람으로 열거나 다른 브라우저에 복사해 연다. 책은 현재 서비스의 PageFlip·사진 배치·뒷표지를 사용한다. 상시 공유 버튼은 뷰어에 넣지 않는다.
4. 상황 선택에서 빈 앨범·저장 중·글귀 한 개 미완료·발급 실패·응답 끊김·복사 실패·저장 실패·발급 중 닫기·긴 이름·일시 중지를 비교한다.
5. 공유 후 가상 사진·글귀를 업데이트하면 다음 입장에 반영되고 이미 열린 책은 유지된다. 뒷표지의 내 앨범은 방문자 자신의 목록이다. 로그인 및 타 계정은 가상 상태이며 실제 OAuth 검증이 아니다.

## 구현 경계와 재실행

이 폴더는 독립된 Python 메모리 모델과 정적 UI다. 제품 모듈·DB·저장소·AI·메일·자격증명을 import하지 않는다. 합성 SVG는 이 작업에서 만든 샘플이며 개인 사진이 아니다. 서버 종료 시 체험 발급 상태는 사라진다. 내부 owner 경로와 발급 토큰은 output에만 저장하고 커밋하지 않는다.

- `model.py`: 가상 앨범·단일 링크 재사용·받는 사람 자료·실패 시나리오.
- `server.py`: 정적 자산 whitelist·가상 owner/recipient API·Origin/Host 확인. 이 자체를 제품 보안 구현으로 사용하지 않는다.
- `preview.js` / `preview.css`: A/B/C 소유자 체험과 공유 패널.
- `visitor.js`: 가상 세션으로 실제 책 코드를 연결하고 방문자 내 앨범을 시뮬레이션.
- `prepare.py`: 현재 저장소의 CSS/사진 배치/책/뒷표지 코드를 독립 자산으로 빌드. PageFlip MIT 고지를 그대로 포함한다. 기존 이식 출처는 `frontend/public/nfc-assets/README.md`를 따른다.

```sh
python3 docs/prototypes/album-share-link/prepare.py --frontend-image mori-ai:album-management-frontend-20261105
python3 -m unittest discover -s docs/prototypes/album-share-link -p 'test_*.py'
python3 docs/prototypes/album-share-link/server.py --root output/album-share-link-review --lan <현재-LAN-IP> --port 18230 --https-port 18231 --cert <신뢰된-로컬-인증서> --key <인증서-키>
```

준비 스크립트는 설치된 frontend build 이미지의 esbuild를 network none으로 실행한다. 이미지가 없다면 기존 프로젝트 frontend builder를 먼저 준비하며 의존성을 자동 내려받지 않는다. 외부 환경 파일이나 키를 출력하지 않는다.

- 브라우저 UI 확인34개 통과: A/B/C 첫 공유·재복사, 재시도, 수동 복사, 저장 실패, 늦은 발급 응답, 중지 취소/재개, 패널 닫기 초점 복귀, 각 상태 안내. 이 반복 검사는 Clipboard stub을 쓰며 실제 기기 복사 인수와 구분한다.
- 별도 실제 Chromium 버튼 클릭에서 native Clipboard 복사 성공 표시를 확인했다. 320×568/393×852/1024×800의 패널과 목록을 점검했다. 가로 넘침 없고 주요 복사 버튼 약52px/목록 공유 버튼44px. 토스트가 dialog 뒤로 가려지던 문제와 상위 CSS import 누락을 수정했다.
- 실제 책 코드의 페이지 넘김과 뒷표지·방문자 목록을 브라우저에서 확인했다. 비로그인 상태는 로그인 안내, 가상 타 계정은 방문자 자신의 목록으로 연결됐고 소유자 목록 노출은 없었다. 해당 경로 콘솔 오류는 없었다. 기기 공유 창, 실제 Android/iPhone 파일·메모리·NFC 태그 인수는 별도다. 제품 전체 테스트는 제품 코드 변경이 없어 재실행하지 않았다.
- 실행 증거·스크린샷은 ignored `output/album-share-link-review/`, 브라우저 로그는 `/private/tmp/mori-share-link-*.log`에 둔다. 합성 링크도 로그를 공개 문서에 붙이지 않는다.

## 사용자 선택 뒤 제품 구현 원칙

기존 goods NFC의 `purchase_id` 의존성을 우회하려고 가짜 구매를 생성하지 않는다. 앨범에 연결된 익명 감상 권한을 별도로 설계하고 기존 NFC 태그 해석과 저장된 전체 주소를 보존한다. 구매와 무관한 소유자 발급 API·중복 요청의 원자적 재사용·로그인/소유권/CSRF·사진별 접근 범위·원문 키 재조회 정책은 계약/샘플/migration/테스트와 함께 구현한다. `/albums/{id}/view`의 소유자 인증을 풀지 않는다. 구매자 자료·운영자 NFC bundle 공개 범위를 임의로 넓히지 않는다.

기본은 발급 전 비공개, 명시 발급 후 전체 주소를 아는 사람의 읽기 전용 접근이다. 전체 주소를 가진 사람이 다시 전달할 수 있다는 점은 공개 범위에 포함된다. 사진·글귀 변경은 다음 감상부터 반영한다. 뷰어 안에 상시 버튼을 추가하지 않고 마지막 장의 방문자 ‘내 앨범’ 연결을 유지한다. 메신저 표지 미리보기나 물리 NFC 접촉을 증명하는 기능으로 약속하지 않는다.

## 브라우저 근거

비동기 네트워크 요청 후 Clipboard/Share 동작은 브라우저의 사용자 활성 상태와 보안 컨텍스트 제약을 고려해야 한다. 그래서 B는 준비와 복사를 명시적인 두 번의 클릭으로 나눈다. 이는 휴대폰 실측 결과가 아닌 플랫폼 문서에 근거한 설계 판단이다.

- [WebKit Async Clipboard API](https://webkit.org/blog/10855/async-clipboard-api/)
- [WebKit User Activation API](https://webkit.org/blog/13862/the-user-activation-api/)
- [W3C Web Share](https://www.w3.org/TR/web-share/)
- [Google Photos 링크 공유 관리](https://support.google.com/photos/answer/6280921?co=GENIE.Platform%3DDesktop&hl=en)
