직전 구매 후 작업에서 구현한 것은 구매당 전용 앨범·자료·QR·선물 등록·메일 전달 기반이다. 기존 사진첩의 개설/생성/확인/감상/편집 정책을 유지했으므로, 그 작업의 완료를 TASK-002 전체 기획의 구현 완료로 해석하면 안 된다.

후반 기획은 “모든 실물마다 반드시 서로 다른 앨범”으로 고정하지 않았다. **굿즈 하나가 여는 앨범은 하나이되, 같은 앨범을 여러 굿즈가 열 수 있는 구상**이 추가됐다. 기본 개인 구매·수령자가 채우는 선물과 공통 앨범 답례품을 나눠 봐야 한다. [P3]의 360행 이후와 [P7]의 10절이 근거다.

현재 DB는 `GoodsTestPurchase.design_id UNIQUE`, `album_id UNIQUE`여서 **디자인1 : 테스트 구매1 : 전용 앨범1**이다. 별도 `GoodsDesign.album_id`는 기존 수동 연결용이며 같은 앨범을 여러 디자인이 참조하는 구조 자체는 가능하다. 그러나 이것만으로 수량 주문·여러 실물 태그·공통 앨범 상품을 지원한다고 볼 수는 없다. 구매와 실물의 개수를 표현하는 데이터가 없기 때문이다. [C02] [C03]

기존 독립 앨범 데이터를 보존하는 것과 **신규 독립 앨범 생성을 계속 허용하는 것**도 다르다. 전자는 기존 기능 유지 조건이었지만, 후자가 구매 후 앨범 개설 원칙을 우회하게 만드는 상태는 별도로 정리할 대상이다.

**6. 초기 방향과 이미 맞는 부분 / 잘못 누락으로 세면 안 되는 부분**

- 모바일 웹 중심이며 전용 앱 설치를 요구하지 않는다. 첫 진입은 굿즈이고, 로그인 전 디자인 체험·저장 때 로그인 인계가 있다. 비회원3회와 회원 추천 제한 해제는 이 저장소의 후속 사용자 결정이다.
- 가로 앨범 사진에 AI 3:4 변환을 적용하고 세로·정사각형은 불필요한 이미지 생성을 생략한다. 사진첩 전체를 그림체 변환하는 상품으로 돌아간 것은 아니다. [C04]
- 원본 파일 장기보관/원본 전환 버튼은 초기 방향에서도 제외였다. 정규화된 서비스 이미지를 쓰는 것이 곧 기획 위반은 아니다.
- 좌우 탭·스와이프·방향키 이동은 있다. 다만 현재 뷰어는 이미지 소스를 바꿔 넘기는 구조이고 별도 책장 말림/3D page-turn 엔진은 없다. 초기의 “책장 넘김 감각” 충족 정도는 시각적 판단 대상이며 탭 이동 기능 자체와 구분한다. TTS/기존 동화 콘텐츠 애니메이션은 추가하지 않았다. [C19]
- BGM은 후속 승인으로 추가됐지만 정적인 BGM 재생을 기획의 사진·영상 재감상 편집본으로 볼 수는 없다.
- 구멍 이동은 AI 원화를 다시 생성하지 않고 화면 합성으로 처리한다. 사진형/그림형의 배경 유지·기본 둥근 사각형은10월23일 후속 사용자 기준이다. 최초 자유형 희망을 이유로 이 후속 결정을 되돌릴 근거는 없다.
- 인증형 NFC 칩의 강한 물리 접촉 증명은 초기 테스트 필수 조건으로 확정하지 않았다. 일반 태그 시험을 허용한 것과, **로그인 없는 NFC 감상 경로 자체를 생략해도 된다는 것**은 다르다. 전자는 후속 연구로 둘 수 있으나 후자는 기획의 핵심 차이다.
- 완성PNG 직접 불러오기·한 번에3가지 비교·마플 전체 편집기 복제·자동 제조 주문을 이번 핵심 기획에 없는 필수 기능으로 확대하지 않는다.

**8. 기획과 맞추는 다음 작업의 우선순위 제안 — 이번에는 실행하지 않음**

1. **상품과 앨범 권한을 먼저 정리:** 기존 데이터는 보존하면서 신규 독립 앨범 개설/사진 처리를 구매 권한과 연결한다. 디자인·구매항목·실물·앨범을 분리해 기본1앨범과 공통앨범 추가 실물을 표현할 수 있게 한다. 초기부터 복잡한 단체 주문 UI를 모두 만들 필요는 없다.
2. **NFC 감상과 QR 관리를 실제로 분리:** 로그인 없는 감상 진입·감상 세션·미디어 접근을 만들고 책장/완성 화면의 전체 감상 우회를 함께 정리한다. 일반 태그의 한계를 문서대로 구분하며 인증칩 심화를 선행 조건으로 만들지 않는다.
3. **앨범 생애주기를 바꾸기:** 전송 뒤 자동 처리/완성, 정상 흐름의 생성·publish 필수 클릭 제거, 완성 후 선택적 사진 변경을 같은 설계에서 다룬다. 버튼만 없애거나 published를 무조건draft로 돌리는 국소 수정으로 처리하지 않는다.
4. **기본20/확장50·자동선별·혼합 입력:** 상품 정원과 입력 개수를 분리하고, 사진/영상 수용·정원 내 선별·실패 복구를 구현한다.50→500 같은 상수 변경만으로 완료될 과제가 아니다.
5. **수정/보관/재감상 정책 연결:** 확정된 최초 NFC감상 시작 조건을 반영하고, 미정 기간·포함량·가격은 실제 기능을 구체화할 때 필요한 항목만 질문한다. 추억 편집본과 보관 연장/유료 재수정은 별도 상태/비용 경계로 다룬다.
6. **운영자 실발송/제작 검증:** 현재 자료로 운영자 테스트1건을 확인한 뒤 공급자 접수·수신함·첨부·수동 제작 재현·NFC 연결을 각각 검증한다. 키 입력만으로 전체 대기 구매를 발송하지 않는다.

이미 정해져 다시 물을 필요 없는 사항: 구매 후 앨범, 기본20/확장50, 영상 포함 합계 정원, NFC와 관리 분리, 전송 후 워커 지속, 일반 구매자/선물 최초 명시 등록, 키링/마그네틱, 모바일 웹 우선.

아직 별도 판단이 필요한 사항: 정확한 수정기간과 추가처리량·유료 재수정 범위/가격, 보관1년 시작/만료/연장료, 공통 앨범의 관리자·시작주체/납부자, 오등록 복구, 실제 제조 프로필/기기 수용 기준. 이 모든 답을 한꺼번에 받아야 기본 흐름을 고칠 수 있다는 뜻은 아니다.

**9. Resend 키와 이번 확인의 한계**

- `.local/goods-delivery.env`: 키가 비어 있지 않음. 값은 출력·복사하지 않았다. `GOODS_MAIL_ENABLED=false`, 단건 구매 필터는 미설정.
- 실행 중18187 web의 Settings: 키 미반영, mail_enabled=false, checkout_mode=test. 파일 입력 이후 컨테이너가 아직 새 값을 읽지 않은 상태로 확인했다. 이번 조사에서는 재시작하지 않았다.
- 실제 공급자 접수/수신함 도착은 이번에 시험하지 않았다. API키의 유효성·발신 도메인/수신 제한도 키 존재 확인만으로 보장하지 않는다.
- 실행 중 서비스의 공개 config에서 최소1/최대50·사진 확장자 목록·test 구매 모드를 읽어 코드와 일치함을 확인했다. 운영 서버는 조사/변경하지 않았다.
- 이번 결과는 코드/계약/기획 대조와 제한된 read-only runtime 확인이다. 이전에 통과한 자동검사·모바일폭 브라우저 검증을 이번에 전부 재실행한 것으로 보고하지 않는다. 실제 NFC 태그·휴대폰·제조·고객 만족 검증 완료를 주장하지 않는다.
