# 미디어 둘째 묶음 로컬 검증 — 2026-10-19

범위는 G2 굿즈 프론트·Task5 가로 AI 정책·Task7 검증 도구 준비다. 세 서브에이전트가 분리된 파일을 구현하고 G2/Task5를 상호 독립 검토했다. 총괄은 검증 도구·공통 계약·빌드 통합을 검토했다. 기존 미커밋 변경은 보존했으며 기존 moriai 소스 이식, QA/운영 변경, 배포, 유료 AI 호출은 없다.

## 구현과 호환성

- G2: `frontend/src/features/goods/preprocess.ts`는 원본20MiB를 먼저 제한하고 JPEG40MP까지 방향 보정·2048/85 축소를 시도한다. PNG/basic WebP12MP, 불확실한 색상/고해상도 PNG/WebP/HEIC은 서버 fallback. 공유 inspectImage 기본12MP는 유지한다. `api.ts`는 오류 status/code/details/retry/requestId 및401 이벤트를 보존하고 인증된 정규화본 미리보기를 디코딩한다. `GoodsWorkspace.tsx`는 후보 업로드+미리보기 성공 이후 교체한다.
- Task5: `generation/output_policy.py`를 중심으로 생성 접수/완료/게시/편집/뷰어/미디어 접근이 같은 결과 검증을 사용한다. 새 run의 세로·정사각형만 기존 normalized/thumbnail ID·해시를 재사용하며 이미지·optimize attempt를 만들지 않는다. 글귀는 유지한다. 가로 AI 결과만 정확3:4·2048/1MB를 검사한다. 저장 비율은 그대로, 화면은 cover/center다.
- 기존 예약 validation_config와 run snapshot은 덮어쓰지 않는다. 구 run은 exact3:4·기존 optimize 정책으로 재개한다. 구 사진의 새 run은 원래 크기가 없을 때 실제 normalized 크기를 snapshot에 명시한다. 전역 이미지2·글귀4는 이번 묶음에서 변경하지 않는다.
- 계약은 공통v1.10·굿즈v1.2로 갱신했다. 제품코드는 저장소 기존 모듈을 재사용하며 외부 저장소 이식/새 의존성 추가는 없다.

## 검토와 로컬 검사

G2 검토에서 생성POST 응답 전에 이탈하면 빈 후보 work ID를 잃는 문제를 발견했다. 생성 응답은 회수한 뒤 취소 여부를 검사해 후보를 폐기하도록 수정했다. 수정 전 회귀 실패를 확인하고 수정 후 G2/workflow20개 및 TypeScript를 통과했다. Task5 독립 검토에서 구체적 결함은 발견하지 못했다.

Task5 초기 선택검사49통과/fixture2실패는 완료 집계 fixture가 동결된 normalized/thumbnail 참조를 임의 결과로 교체한 문제와, legacy 정리 fixture의 canonical thumbnail key 중복 INSERT 문제였다. 구 run fixture를 명시적으로 legacy로 고정하고 이후48개, 추가35개 범위 검사를 통과했다. mock provider 검사는 실제 외부 AI 성공·성능 근거가 아니다. 최종 전체 결과는 아래에 기록한다.

## 실제 Chromium·서버 codec 관측

합성 비식별 입력을 실제 로컬 Chromium에서 `prepareGoodsSource`로 처리했다. Canvas stub 결과와 구분하며 실제 HTTP 전체 UI 흐름 검증은 아니다. 원시 관측은 `미디어-둘째묶음-browser.json`에 저장한다.

| 입력 | 브라우저 결과 | 이후 굿즈 서버 codec |
|---|---|---|
| 20MP JPEG, EXIF6, 325,224bytes | 1638×2048 WebP, 7,372bytes | 1638×2048, 6,806bytes |
| 20MP PNG, 67,366bytes | 원본 fallback | 2048×1638, 6,896bytes |
| 800×640 WebP, 1,468bytes | 원본 유지 | 800×640, 1,504bytes |
| 800×640 PNG, 3,064bytes | WebP1,850bytes·확대 없음 | 800×640, 1,458bytes |
| 합성 HEIC EXIF6, 1,026bytes | MIME있음/빈MIME 모두 원본 fallback | 640×800 WebP1,412bytes |

JPEG의 EXIF6 보정 결과 네 모서리 색상을 서버 Pillow exif_transpose와 비교해 채널별 오차15미만을 확인했다. 이는 합성 방향 검사이며 인물 사진의 주관적 화질 검증이 아니다. 굿즈는 기존 v2 서버 정규화 경로이므로 브라우저 WebP도 재인코딩할 수 있다. 앨범 v3 재사용 보장을 굿즈에 확대하지 않는다.

## 검증 도구 준비와 남은 범위

`reuse_load_probe.py`·`verify-media-reuse.sh`는 동일 합성 입력의4096/90·2048/85·1MB 상한 결과와 실제v3 재사용을 비교한다. 해시/픽셀/바이트/크기/메타데이터/alpha/codec child sampled RSS/cgroup peak를 기록한다. 네트워크 없는 고유1GiB 컨테이너와 새 출력 디렉터리를 사용한다. 도구 단위8개(추가 실제 소형 HEIF 촬영일 보존 검사 포함 최종9개) 및 작은4종×3설정+4재사용 스모크 통과. 스모크 peak72,142,848bytes, OOM/limit이벤트0은 작은 도구 검사값이며 부하 인증이 아니다.

`full-environment`는 미구현을 명시하고 exit2로 종료한다.1800초 watchdog은 시간 상한일 뿐30분 지속 부하가 아니다. 40MP/HEIF 전체 codec matrix, DB/web/proxy/worker합산2GB·30분 혼합 부하,50장·이미지4/글귀4, p50/p95·idle RSS·중복작업 계측은 후속 Task6/7/G3다. 실제 iPhone/WebKit·모바일 이탈/복귀·인물/머리카락/저조도 화질·BGM 실제 브라우저 회귀 및 운영422 원인 확인도 미완료다.

최종 프론트 Docker 빌드(TypeScript/Vite 포함)와 전체 테스트131개가 통과했다. G2 생성응답 회수 수정은 독립 재검토에서 해결 확인했다. Task5 마지막 확장 방향·legacy/new 모의 실제 executor14개도 통과했다.
