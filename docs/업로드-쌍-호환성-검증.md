# 본문·썸네일 쌍 업로드 및 기존 호환성 — 2026-10-19

범위: 계획 Task 2의 계약·nullable migration·선택적 쌍 업로드 전송과 로컬 검증. 현행 계약1.7에 이미 계정 승인 정책이 있어 새 계약 번호는1.8로 정했다. 제품 재사용·2048/85·가로 전용 AI·병렬4는 아직 구현하지 않았다. 운영 배포·운영 migration·실제 R2/OpenAI 호출 없음.

## 변경

- 예약 요청에 선택 thumbnail bytes/hash/MIME, 응답에 thumbnail_upload를 추가했다. 본문과 같은 upload/page에 속하며 독립 임시 저장 키를 사용한다. 썸네일도 앨범 전송량에 포함한다.
- local PUT은 경로별 서명·세션·소유권·CSRF·만료를 확인한다. R2는 기존 조건부 PUT 서명을 사용한다. complete는 두 파일의 실제 크기/hash를 모두 확인한 뒤 validation job을 생성한다.
- validation은 임시 썸네일의 실제 WebP·단일 프레임·480px·200000bytes 제한을 child에서 확인한다. 아직 업로드 썸네일을 표시용으로 채택하지 않고 서버 생성 썸네일을 사용한다.
- ready commit 후 source/임시 썸네일을 정리한다. 만료·거부24시간 정리, 페이지 삭제 및 늦은 PUT tombstone sweep도 확장했다.
- `0007_upload_pairs`는 Upload 썸네일 참조/용량 및 향후 방향 기록용 Page 크기를 nullable로 추가한다. 기존 JSON과 데이터는 backfill하지 않는다.
- 쌍 요청은 upload_protocol_version=2, 기존 validation_config.version=1/media normalization2 유지. 기존 run config/AI 동작은 수정하지 않았다.
- 현행 계약의 ‘모든 임의 payload 제거를 위한 재인코딩’ 표현을 수정했다. 실제 재사용 구현 전까지 codec v1/v2의 동작은 유지한다.

## 검증 이력

- 최초 신규4개 검사: 전부 실패(새 선택 필드 미지원). `/tmp/mori-pairs-red.log`.
- 첫 구현 후 신규·기존 업로드 검사: 36 passed / 1 failed. 실패는 새 thumbnail:null이 기존 idempotency hash에 포함되어 구 예약 재시도가409인 문제였다. null 선택 필드를 해시에서 제외해 수정했다. `/tmp/mori-pairs-green.log`.
- Docker Desktop 시작 후 테스트 전용 임시 Compose project/DB/volume을 사용했다. 기존 QA 환경·DB·사진을 변경하지 않았다.
- 테스트 runner의 첫 이미지 선택은 아키텍처 불일치로 실행되지 않았으며, 기존 amd64 `mori-ai:ai-tests`로 변경했다. 새 외부 이미지를 설치하지 않았다.
- 신규 쌍 업로드8개를 포함한 기존 전처리/R2 HTTP 집중 검사: **38 passed (19.72s)**. `/tmp/mori-pairs-final-focused.log`.
- 전체 backend: **884 passed, 1 failed, 10 subtests passed (399.51s)**. 유일한 실패는 삭제 sweep의 기존 기대 경로6개가 새 upload_thumbnail 경로로7개가 된 것이다. 기대 개수를 수정하고 새 경로 포함 여부를 추가했다. 제품 코드 추가 변경은 없었다. `/tmp/mori-pairs-full.log`.
- 수정 후 sweep 회귀 파일 재실행: **5 passed (3.27s)**. `/tmp/mori-pairs-sweep.log`. 전체 모음은 다시 실행하지 않았으며 최초 전체 실행 실패와 수정 후 집중 통과를 구분한다.
- 격리 PostgreSQL17 migration upgrade→downgrade base→upgrade 및 Alembic schema check 통과. 각 테스트 프로젝트/volume은 종료 후 제거했다.
- 변경한 frontend API 타입의 TypeScript 검사 통과. 전체 frontend 빌드/브라우저 검사는 이번 단계에서 실행하지 않았다.
- 계약 샘플 JSON 파싱 및 git diff --check 통과. 독립 읽기 전용 코드 검토에서 차단 결함은 없었고, 추가 경계 검사와 계약 표 보완을 반영했다.
- 기존 예약의 null 선택 필드 해시 호환을 회귀 검사로 확인했다. 기존 진행 run의 설정·정규화 정책을 수정하지 않았으며 전체 검사에서 해당 생성/복구 검사는 통과했다. 운영의 실제 예약/run 데이터를 조회하거나 변경하지 않았다.
